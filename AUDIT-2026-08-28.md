# WordBuddy Full Audit — 2026-08-28

Status: **remediation complete**. No confirmed critical/high code finding is
left open in the audited worktree.

This was a repo-wide audit of the Tauri/Rust backend, React frontend, Chrome /
Edge Manifest V3 extension, persistence, privacy invariants, dependency graph,
CI/release workflows, public security documentation, and current uncommitted
work. The worktree was already dirty at the start; those edits were preserved
and audited as part of the candidate result.

## Executive result

- Privacy boundaries now fail closed before browser/native field reads.
- Cross-window widget delivery is readiness- and mode-gated, serialized, and
  replays only the current bounded snapshot.
- Native apply revalidates target identity/text, handles UTF-16 correctly, and
  reports revert failures honestly.
- Browser relay payloads are authenticated, validated, byte-capped, and scoped
  to top-level non-incognito pages with explicit optional origin grants.
- Chat-turn persistence is a real single-connection SQLite transaction.
- Analytics aggregation, local-day/DST behavior, vocabulary percentages,
  retention, cache-hit accounting, and week boundaries are corrected.
- The Rust lockfile no longer contains any active known vulnerability.
- CI and tag releases now run reproducible format, lint, test, build, and full
  dependency-audit gates.

## Confirmed findings and fixes

| ID | Severity | Finding | Resolution |

| A01 | High | Browser privacy preferences loaded asynchronously and checker activity could start before them, allowing reads during startup. | Checker now fails closed until both local and authenticated app preferences load; every gate transition clears cards/underlines. |
| A02 | High | Password-only filtering missed credential, payment, OTP, API-key/token/secret, contenteditable, and GitHub-sensitive fields. | Conservative pre-read classification added at every read boundary; GitHub inline checking is hard-off. |
| A03 | High | Native password detection failed open on UIA errors and apply could re-resolve a different control between probe and write. | Password checks fail closed; HWND/process/text identity is revalidated at the write boundary and focus races abort. |
| A04 | High | UTF-16 issue offsets were used as UIA character counts, corrupting replacement selection after astral characters. | Native selection rebases UTF-16 spans against current text; astral and combining-sequence cases are covered. |
| A05 | High | Lazy widget creation lost the first issues/text or palette events, and concurrent mode changes could replay into the wrong surface. | Added widget-ready/mode-ready handshake, serialized mode tasks, current-snapshot replay, stale-task revalidation, and a corrected anchor wire shape. |
| A06 | High | Widget fixes could apply against stale/wrong field text; ResizeObservers leaked; palette consumed unrelated stream events. | Apply stays disabled until a target-matching text snapshot arrives; observer/listener lifetimes and stream ownership are bounded. |

## Residual, environment-dependent evidence

These are not open code defects, but they require real environments rather
than this workspace:

- Browser E2E for permission prompts, dynamic injection, underlines, popup,
  and live relay behavior was not available. The local manual fixture is
  `wordbuddy-extension/test-pages/live-check.html`.
- Native synthetic input and install/launch/uninstall were not exercised on
  the user's active desktop. macOS AX and Linux AT-SPI behavior still rely on
  their platform CI/probes and eventual real-machine smoke runs.
- The interactive OS-vault smoke is intentionally ignored in hermetic tests;
  it must run in a logged-in desktop session.
- RustSec reports 19 informational upstream warnings, primarily Tauri's
  GTK3/glib stack and transitive build/runtime crates. One glib iterator API
  is marked unsound upstream; WordBuddy does not call that API. These cannot
  be removed without upstream Tauri/dependency migration and should be
  rechecked on each lockfile refresh.
- Binaries remain unsigned and auto-update remains disabled until signing
  credentials exist; this is an external release decision, not a code fix.
