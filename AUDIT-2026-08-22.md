## 2. Executive summary

No Critical findings (nothing remotely exploitable, no user-file destruction,
no secret exfiltration path outside the flows below). But the sprint left
**7 High-severity defects** after second-pass review (an initial eighth,
F8, was downgraded — see its entry), clustered in three themes:

1. **Broken privacy controls (extension + native).** Two advertised privacy
   guarantees do not hold in code: the extension's "don't send form-field
   values" toggle never reaches the inline checker, and password-field
   detection *fails open* in the native reader/writer.
2. **Shipped-broken features with zero test coverage.** Writing analytics
   aggregation fails whenever there is data to aggregate; the widget/hotkey
   toggles are silently ignored due to a serde casing mismatch.
3. **Input-corruption paths.** The UIA apply path treats UTF-16 offsets as
   UIA character units (corrupts text containing emoji/astral chars), and a
   snippets off→on toggle permanently leaks the low-level keyboard hook,
   double-processing every keystroke system-wide.

Invariant scorecard:

| Invariant | Verdict |
|---|---|
| INV-PRIV-001 (password fields never read/written) | **Violated on error paths** — detection fails open (F5, M13) |
| INV-PRIV-002 (raw field text never persisted) | **Holds** in `analytics/*` (verified); caveat L2 (per-event host/process metadata persisted) |
| INV-PRIV-003 (ambient keystrokes never reach an LLM) | Holds in native paths; **extension checker forwards typed text** whenever Browser style checking is on — disclosed nowhere (M11/E-policy) |
| INV-EXCL-001 (excluded targets get nothing before read) | **Holds** — enforced inside the reader pre-read, with regression test (`text_monitor.rs:375-382`, `:727-752`) |
| INV-OFFSET-001 (UTF-16 across Rust↔JS) | **Read path correct and well-tested; write path violated** (F4) |

## 3. Findings

Severity: High / Medium / Low / Info. Confidence: **verified** means a second
independent read of the cited lines confirmed the reviewer's claim;

### High

**F1 · Analytics aggregation fails on every non-empty DB — daily stats never populate.**
`src-tauri/src/analytics/jobs.rs:16-34` · confidence: verified (read directly)

`aggregate_and_store` SELECTs `ts, word_count, COALESCE(vocab_unique,0),
COALESCE(vocab_rare_pct,0.0), issue_counts_json, rule_counts_json` but the row
reader maps index 1→`_surface: String`, 2→`_target: String`, 3→`words: u32`.
Index 1 is now `word_count` (INTEGER); `row.get::<_, String>(1)` returns
`InvalidColumnType`, so the function errors on the first data row. Both the
nightly scheduler (`jobs.rs:382`) and `analytics_aggregate_now` therefore
always fail once `check_events` is non-empty; `daily_stats`, weekly reports,
summary, and export serve nothing. Reader indices were written for the
pre-vocab column list and not updated. No test covers this function.

**F2 · `widget_enabled` / `selection_hotkey_enabled` toggles silently ignored (serde casing mismatch).**
`src/App.tsx:76-104` ↔ `src-tauri/src/config.rs:9-12` · verified

`get_settings` returns `AppConfig`, which has no `#[serde(rename_all =
"camelCase")]` → snake_case JSON. App.tsx reads `cfg.widgetEnabled` /
`cfg.selectionHotkeyEnabled` — always `undefined` — and `undefined !== false`
evaluates true, so the floating widget appears even when disabled and the
Ctrl+Shift+W selection hotkey fires even when toggled off. The same payload is
consumed correctly snake_case in `app.context.tsx`, proving the wire format.

**F3 · Snippets off→on toggle leaks the WH_KEYBOARD_LL hook; every keystroke then processes twice.**
`src-tauri/src/snip_hook.rs:188-308` · verified (structural race; timing-dependent)

`stop()` sets `WATCHDOG_TRIPPED=true`; the pump loop only observes the flag
*after* `DispatchMessageW` (:275-277) and otherwise blocks in `GetMessageW`.
A subsequent `start()` resets the flag to false (:198) and installs a second
hook, overwriting `HOOK_HANDLE`. If the old pump has not dispatched a message
between stop and start, it never sees `true`, never unhooks — two live hooks
run `hook_proc` per keystroke: doubled ring characters ("tthhee"), possible
double expansions. Any Settings off→on toggle can trigger it.

**F4 · Apply path passes UTF-16 offsets as UIA `TextUnit::Character` counts — misselection corrupts text containing astral chars.**
`src-tauri/src/apply.rs:394-430` · verified mechanism; exact unit semantics per UIA spec suspected

`select_range` walks `move_text(TextUnit::Character, start)` +
`move_endpoint_by_unit(End, Character, end-start)` with UTF-16 code-unit
offsets (INV-OFFSET-001 input contract). UIA character units advance per
Unicode scalar, so each surrogate pair before the span shortens the selection
by one unit; the subsequent synthetic Ctrl+V replaces the wrong characters —
silent document corruption. Notably, the *read* side (`engine/offsets.rs`,
`engine/style.rs`, `splice_utf16`) is exemplary: prefix-sum conversions plus
astral/combining test vectors, and every LLM-returned span is validated by
slice equality before acceptance. Only the UIA write path violates the
invariant.

**F5 · Password detection fails open — a failed UIA property read leads to reading (and writing) password fields.**
`src-tauri/src/text_monitor.rs:387`, `src-tauri/src/apply.rs:363` · verified

Both sites use `element.is_password().unwrap_or(false)`. When the property
query errors — common on non-conforming UIA providers — the field is treated
as non-password and its value is read via ValuePattern/TextPattern (monitor)
or SetValue/paste targets it (apply). INV-PRIV-001 requires password fields to
be detected *before any value read* and never touched; failing open inverts
the guarantee exactly where detection is least reliable. Default to
skip-on-error instead.

**F6 · Extension: the "Don't send form-field values" toggle never gates checker.js.**
`wordbuddy-extension/content.js:116-118` vs `wordbuddy-extension/checker.js` · verified (grep: zero `maskInputs` occurrences in checker.js)

`maskInputs` is consulted only by the DOM scanner in content.js. checker.js —
which watches editable fields and POSTs their full text to `/check` on a
300 ms debounce — never reads it. With the toggle ON, typed text still leaves
the page toward the desktop app (and onward to the configured LLM provider on
style passes), contradicting PRIVACY_POLICY.md:41-44 ("drops whatever the user
has typed"). Pause toggle and excludedHosts remain effective mitigations.

**F7 · Extension: GitHub carve-out absent from checker.js — unsent PR comments sent onward despite policy promise.**
`wordbuddy-extension/content.js:23-26` vs `checker.js:43-45`, `PRIVACY_POLICY.md:45-47` · verified

`HOST_IS_GITHUB` masks values only in the scanner. checker.js's eligibility
gate (`activeAllowed()`) checks only enabled/paused/excludedHosts, so on
github.com it reads PR-comment/review-draft editor text — the exact data class
the policy cites as the reason for always-on protection — and transmits it via
`/check`.

**F8 · DOWNGRADED High → Low on second-pass review — sender validation is hardening, not an exploitable gap.**
`wordbuddy-extension/background.js:10-29`, `manifest.json` · mechanism corrected

The original claim — that any co-installed extension can reach the
`chrome.runtime.onMessage` handler (`_sender` unused) and harvest the relay
token via `{type:'getConfig'}` — does not hold. Messages from other
extensions are delivered to `runtime.onMessageExternal` /
`onConnectExternal`, never to `onMessage` (Chrome messaging docs,
developer.chrome.com/docs/extensions/develop/concepts/messaging);
background.js registers only `onMessage`, and manifest.json declares no
`externally_connectable` key (default: other extensions *may* send, but only
to the External listeners). There is no listener an outside extension can
reach, so the token-harvest, forged-`scan`, and LLM-billing scenarios have no
entry point.

What remains true: `_sender` is never inspected, so nothing enforces that
message senders are this extension's own content scripts/pages. Adding the
guard (`_sender.id === chrome.runtime.id && _sender.tab`) is worthwhile
defense-in-depth — it contains the damage if an `onMessageExternal` listener
is ever introduced or a renderer hosting the content scripts is compromised —
but it is not a vulnerability today. Severity: **Low**.

### Medium

**M1 · Widget rewrite palette ignores the user's provider/model.**
`src/components/widget/WidgetApp.tsx:316-326` → `src-tauri/src/llm.rs:233-249` · verified
`stream_response` invoked without model/provider → defaults to Anthropic + hard-coded model. Non-Anthropic users get auth failures routed to the wrong API.

**M2 · Saved-conversation links bypass the phishing-confirm gate used everywhere else.**
`src/pages/History.tsx:247-254` vs gated renderer at :130-147 · verified
Persisted-history markdown links call `open(href)` with no
`confirmExternalLink` and no scheme validation; safeOpen.ts's own threat model
names chat history loaded from SQLite. Session renderer in the same file does
it correctly — inconsistent second pattern.

**M3 · Broadcast stream events cross-contaminate main chat and widget palette.**
`src-tauri/src/llm.rs:325,383,470` (`app.emit`) × global `listen()` in ChatBar.tsx:110-160 and WidgetApp · mechanism verified, runtime delivery suspected
Both surfaces subscribe globally to `chat_stream_chunk/complete`; a widget
rewrite appends chunks into the main window buffer and persists a phantom
message via stale `lastUserMsgRef`; `STREAM_GENERATION` makes concurrent chat
and rewrite mutually abort each other. Needs window-scoped events or labels.

**M4 · `saveTurn` BEGIN/COMMIT may fragment across pooled connections.**
`src/lib/db.ts:165-191` · suspected (needs pool-config/runtime confirmation)
tauri-plugin-sql checks out a connection per execute; nothing binds the
transaction to one connection. Under concurrent first callers the
atomicity guarantee can silently vanish.

**M5 · Debounce never restarts on continued typing — checks fire mid-sentence every ~300 ms.**
`src-tauri/src/text_monitor.rs:280-299` · verified
`changed_at` is set once per transition into Pending::Debounce; new snapshots
for the same field don't refresh it. Continuous typing degenerates to a
throttle; widget offers fixes against text the user already moved past
(apply aborts on drift → churn). Test comment at :787-793 (`change_debounces_then_checks`,
"debounce restarts via key match + changed text") claims debounce restarts; nothing does.

**M6 · Apply target re-resolved without re-verifying identity/content.**
`src-tauri/src/apply.rs:382-412` · suspected
`set_value`/`select_range` call `resolve_target` again after `probe()` verified
text equality; a focus change between probe and write lands the correction in
a different element whose content was never compared.

**M7 · Clipboard restore race around fixed 500 ms delay; failure modes swallowed.**
`src-tauri/src/clipboard.rs:260-286` · suspected
Slow paste targets may read the clipboard after restore swapped it back;
restore failure folds into result such that a landed paste reports failure;
mid-loop failure can leave clipboard emptied; readback mismatch only eprintln!s.

**M8 · `monday_of` returns Sunday, not Monday.**
`src-tauri/src/analytics/jobs.rs:290-293` · verified arithmetic
`d - ((d + 4) % 7)` yields most-recent-Sunday (epoch day 0 = Thursday).
Weekly buckets, `weekly_reports` keys, report headers, and prior-week deltas
are all shifted one day. Fix: `d - ((d + 3) % 7)`.

**M9 · Windows DST offset applied without checking DST is active; frozen at startup.**
`src-tauri/src/analytics/aggregate.rs:48-66` · code path verified; runtime skew suspected
DaylightBias chosen whenever nonzero rather than when DST is in effect →
one-hour bucket skew during standard time; `OnceLock` cache never refreshes
across a DST transition. Non-Windows silently uses UTC.

**M10 · No retention/deletion path anywhere in analytics.**
`src-tauri/src/analytics/db.rs:41-95` · verified
No DELETE/TTL/cap on `check_events`/`rewrites`/`weekly_reports`;
`save_report` writes unbounded `Documents\WordBuddy\reports\*.md`. No
user-facing clear-analytics control. Retention gap for a privacy-first product.

**M11 · PRIVACY_POLICY.md does not match extension behavior.**
`wordbuddy-extension/PRIVACY_POLICY.md:16-33,54-57` · verified
"Data never leaves your machine" is false whenever Browser style checking is
enabled: `/check` text reaches api.anthropic.com / api.openai.com /
googleapis / groq / openrouter (`src-tauri/src/llm.rs:89-141`). The policy's
collection list omits the checker feature entirely and the `<meta
name="wordbuddy-*">` harvesting (content.js:60-76). Correctness checking
itself is local (harper-core) and the style pass is opt-in with
`WB_DISABLE_LLM` kill switch — but the extension discloses none of this.

**M12 · Scanner masking bypassed for contenteditable; no credit-card heuristics with `all_frames` injection.**
`wordbuddy-extension/content.js:113-125`, `manifest.json:16-21`, `checker.js:53-62` · verified
textContent-first fallback captures rich-editor text regardless of maskInputs
or HOST_IS_GITHUB. Neither script detects `autocomplete=cc-*`/cardnumber/CVC
fields, while `all_frames:true + match_about_blank:true` injects into embedded
payment iframes on matched hosts. Password exclusion itself is solid in both
scripts.

**M13 · API keys stored as plaintext JSON (no OS vault).**
`src-tauri/src/config.rs:10-12,199-225` · verified
Single plaintext file holds every provider key. 0600 on Unix only; Windows
relies on inherited profile ACLs (same for the relay token file,
extension.rs:345-370). Bounded to same-user attackers; DPAPI/keychain is the
standard control. Keys verified never logged.

**M14 · CI/release supply-chain hygiene.**
`.github/workflows/ci.yml:53-54,62-71,100`; `release.yml:79,82,87-88` · verified
(a) `npm install` instead of `npm ci` in both workflows — lockfile not enforced
at build time; (b) all actions tag-pinned, incl. `tauri-apps/tauri-action@v0`
running with `contents:write`; (c) the INV-TEL-012 grep step greps
`src/lib/telemetry/` which does not exist, conflating grep exit 2 (error)
with exit 1 (no match) — the gate passes vacuously and would survive any
rename. Positives: no `pull_request_target`, no untrusted interpolation into
`run:` blocks, vitest wired into CI, updater plugin deliberately removed.

## 4. Verified good (checked and holding)

Worth recording so future changes don't regress these:

- **Relay server core**: constant-time token compare, 256-bit CSPRNG token,
  one request per connection (`Connection: close`) — no smuggling; no shell
  spawns anywhere in the backend (no command injection); week_start
  integer-validated before filename use (no traversal); deliberate no-CORS
  posture; per-connection timeouts; bounded highlight queue.
- **UTF-16 read path**: `engine/offsets.rs` prefix-sum conversions with
  astral+combining test vectors; harper spans converted at a single site with
  an invariant test; every LLM span validated by slice equality before
  acceptance (`engine/style.rs:118-160`).
- **Exclusion-before-read ordering** (INV-EXCL-001) enforced inside the
  reader before any pattern/value read, with regression tests.
- **spawn_blocking COM isolation** consistently applied on monitor, apply,
  and a11y UIA paths.
- **Mutex poisoning convention** (`unwrap_or_else(|e| e.into_inner())`)
  followed throughout; single-flight apply guard; clipboard snapshot/restore
  with CF_UNICODETEXT readback verification.
- **Frontend listener discipline**: consistent safeListen/cancelled-flag
  cleanup; ref-based stale-closure avoidance; react-markdown without raw
  HTML (no XSS sink found in either webview or extension; extension renders
  via textContent only); parameterized SQL on both db layers.
- **Supply chain**: lockfiles clean (100% crates.io/npmjs sources, no
  typosquat candidates spotted); direct deps all MIT/Apache-2.0/ISC —
  license verdict: **compliant** with the no-copyleft rule (transitive deps
  spot-checked, not exhaustively enumerated).

## 6. Coverage & limitations

Fully read: all of `src-tauri/src/` (both reviewers overlapping on the hot
paths), all frontend `.tsx/.ts` except `index.css`, all 10 extension files,
workflows/config/scripts. Skimmed at grep level: test-module tails of

Not exercised at runtime: this is a static audit. Items marked *suspected*
(M3, M4, M6, M7, M9, L4) need runtime confirmation on a real Windows session;
F3/F4 mechanisms are code-confirmed but their worst-case timing/UIA-unit
behavior should be reproduced manually (toggle snippets off→on; apply a fix

Suggested fix order (by risk ÷ effort): F5+F6+F7 (privacy controls, all
small diffs) → F1/F2 one-liners → F3/F4 (need careful concurrency/
UIA work) → retention decision (M10) → CI hygiene (M14).
